# Public-source and privacy policy

Every file in this public repository and its releases must be safe to publish.
An ignored file is not an exemption for storing private information here.

- Product procedures and plan assertions need independently accessible public
  Moovs Help/product sources. Read the article body, not just search snippets.
- Official public host/vendor guidance may support its stated scope, not imply
  Moovs account access, integration, entitlement or a successful outcome.
- Distinguish public Help prose, dated product captures, illustrative training,
  recommended checks and actual authorized current observations. Do not invent UI.
- Keep private code, internal source paths/commits, feature flags, customer/demo
  records, private links, screenshots, transcripts and credentials out entirely.
- Use clearly fictional test examples. Account observations are for their
  authorized task, not public training fixtures or source claims.
- Report conflicts and missing documentation honestly. Neither public sources
  nor skill installation grants action permission or overrides host safeguards.
- Review every public Git file and the packaged bytes, links and checksums.
  A parser/package check is not actual browser or every-feature acceptance.

Public Help is the product-guidance source of truth. Local references retain
review dates and bounded scope; update the public source first when possible.
