# Locations and precise pickup/drop-off Points

Reviewed 2026-10-16 against the complete public Help article. It lists **Pro and
above**; confirm actual company access/role before a gated edit. A Location is a
saved venue/address/boundary, not a pricing zone or a company branch. Operator
performs every field/map/selector change, save and deletion; never use live edits
as a preview. Give only the requested workflow. No trip is needed just to manage
a Location; an existing trip is needed only when choosing its pickup/drop-off Point.

## Create a Location

1. Identify the intended venue and operator-approved main address, boundary and
   precise Points. **Settings > Locations > Create**; operator enters its name,
   selects the mapped main address and chooses **Next**.
2. Operator draws the boundary, clicks its first vertex to close it, then **Next**.
   A boundary needs **3-25** map vertices. Main address and boundary cannot be
   edited after creation, so review them before continuing.
3. Operator places a pin **inside** the boundary, labels it and chooses **Add
   point** for each intended Point. Keep **1-10 Points**, uniquely named within
   that Location. Do not guess pins or silently use the venue entrance.
4. Operator chooses **Save**. Review the resulting overview's name/main address,
   closed boundary and exact Point labels/pins. An uncertain save needs state
   inspection before retry, not a duplicate Location or a test booking.

## Choose a saved Point on a trip

1. Identify the exact existing quote/reservation, trip and stop, plus intended
   Location/Point. Use an address inside its saved boundary; a Point selector
   appears below the address. Overlapping Locations group their own Points.
2. Operator chooses the correct Location's named Point, not a similarly named
   Point in another venue. **Google default pin** is the alternative when the
   standard venue destination is intended; do not override the business choice.
3. Operator completes/saves only the intended trip edit using the current offered
   controls. The original venue address remains visible; the Point adds its label
   and map links use its precise navigation data. Compare that same stop's saved
   label, venue address and intended map destination before claiming completion.
   Help says the Point survives supported trip/stop-order changes; after an
   intended change, still compare that same stop rather than assuming any edit is safe.

## If Locations or its Point selector is missing

- Missing **Settings > Locations**: check the company's supported plan and your
  permission without buying or changing access. If still absent, prepare a private
  Moovs Support question for the operator to review/send through chat.
- Missing selector: check the intended mapped address is inside the saved boundary
  and that Location has at least one **active Point**. Operator may reselect the
  intended address from search results; this is a field change, not a read-only
  test. Recheck the address/Point and save only the intended edit with supported
  controls. Do not move a pin, delete/recreate a Location or alter a real booking
  merely to diagnose it. Stop for Support if the controls or result stay unclear.

## Rename a Location or replace a Point

1. **Settings > Locations > intended Location**; review its existing boundary and
   Points. Confirm the requested new name or exact old/new Point, preserving
   unrelated Points. Operator chooses the **Edit icon**.
2. Operator may rename the Location or add/remove Points. To fix a bad pin, remove
   it and add a correctly placed, uniquely labeled Point inside the boundary;
   respect the **1-10** total and preserve at least one valid Point. Review the
   intended changes before any offered submission; the source does not establish
   an edit-save label or universal autosave, so do not invent either.
3. Reopen the intended Location and compare the actual saved name/Point labels and
   positions. If final controls/validation are unclear or the result is uncertain,
   stop and obtain supported guidance/readback before retrying.
4. Main address/boundary cannot be changed here. Recreating an incorrect Location
   is a separately approved delete/create task, not an automatic repair. Existing
   saved trips retain their selected Point data; editing is not a historical rewrite.

## Delete a Location from future use

1. Confirm the exact company/Location and deliberate removal scope, then review
   **Settings > Locations > intended Location**. Do not delete as troubleshooting
   or silently recreate it. Previously saved trip Points remain copied on those
   trips; removal is from **future use**, not cancellation or old-trip rewriting.
2. Operator chooses the **Delete icon** only when ready for that effect. Do not
   assume another confirmation exists; if one is actually offered, operator
   reviews its scope before continuing. Stop on materially different effects.
3. Revisit the Locations list and check the intended entry is no longer available
   for future use, preserving others. Without direct authorized readback, report
   operator-reported, not independently verified. No test booking is necessary.
