# Use an operator-supplied Plus Code for a remote pickup

Reviewed 2026-10-16 from retained July 2025 public caption narration, not literal
frames or current UI. Use the reservation entrypoint's company/access,
task-scoped edit and saved-record checks. This is an alternate pickup input,
not creation of a saved venue Location/Point or live passenger-location sharing.

1. Identify the intended reservation creation and pickup destination. The
   operator obtains the intended **Plus Code** from Google Maps privately and
   checks it refers to the agreed location. This guidance does not authorize
   controlling Google Maps, requesting a passenger's live position or choosing
   a speculative pin for them. The presenter initially struggles to find the
   code; the later narration explicitly names Plus Code, not a share URL or
   arbitrary place identifier.
2. Operator pastes the supplied code into the reservation pickup input only
   when the current offered control supports it. Compare the resulting mapped
   pickup with the agreed destination before saving. The narration suggests
   remote resorts/mountains without a conventional address; it does not prove
   current parser syntax, every code variant or guaranteed map precision.
3. Complete the intended reservation's normal review and operator save choice,
   then reopen the same trip and compare its saved pickup/destination. This
   readback is a recommended check, not a filmed save result. Do not create a
   separate test booking, dispatch a driver or send a customer message to verify
   the code. If mapping fails or is ambiguous, stop for supported guidance
   rather than guessing an address or retrying creation.

The original passenger-to-driver location-sharing question remains a feature
request in the July narration; this static-code alternative does not establish
that feature's current availability. The recording specifies no universal
plan/role entitlement. Without direct permitted readback, completion remains
operator-reported.
