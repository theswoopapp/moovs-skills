# Note audiences and downstream reference review

Reviewed 2026-10-16 from dated webinar narration, not newly inspected current UI.
These enrich existing notes/reference tasks; they are not additional task rows.
Confirm company, exact reservation/trip, requested text and audience before edits.
Apply [task authority](task-authority.md) to edits/saves, including auto-saving controls.

## Choose a note audience and edit from Dispatch

June distinguishes **Internal Comments** for people with Operator-screen access
(such as dispatchers, owners and admins), **Trip Notes** for operator, driver and
customer, and **Driver Notes** for operator and driver. Quote creation also
narrates the Driver/Trip Note audience labels. Use that dated distinction to
choose the intended field; check current displayed audience/access before
sensitive operational content. It is not an exhaustive permissions contract or a
guarantee of confidentiality. Never move internal commentary into a shared note.

On the intended Dispatch ride, the narration describes directly adding/saving
**Trip Notes and Driver Notes** without opening the full trip. If the matching
field/control is offered, operator edits only the intended note and uses its
actual save action. Reopen the same ride/field and compare content/placement;
saved notes do not prove the driver/customer read them. Stop on materially
different controls rather than inventing an editor or test trip.

## Notes during first and return trip creation

April narrates Driver Notes while creating the first reservation trip, and
Driver/Trip Notes while adding a return trip before save. Use matching current
fields to review the intended note text and audience on each leg. General Driver
Notes are distinct from a stop's location-specific Notes; use the latter for
instructions tied to that stop. Operator reviews/saves the intended booking,
then reopens both intended trips/stops and compares note placement and text.
An Operator-side saved-note check does not require a driver login or prove a
driver read it. Do not assume auto-copy between legs, contact-default precedence,
or a merge rule that the sources do not define.
[April 2026, 02:34-02:56 and 08:13-08:39](https://fast.wistia.com/embed/iframe/krp2b1wij8?wtime=154s),
[Driver Notes Help](https://intercom.help/moovs-05c940f1970e/en/articles/6837109).

## Review an external reference on the intended existing output

After the existing per-trip reference save/readback, July narrates its use on
pricing summaries, reservation summaries and invoices. Ask which existing output
needs the PO/reference, then privately open that intended summary or invoice
using supported current controls. Compare the exact trip/reference there; if
missing, report that specific artifact mismatch rather than overwriting other
trips, regenerating/sending documents or promising every PDF/version propagates.
A reference does not prove payment or customer approval. Protect real identifiers.
