# Enable future-reservation deposits using the configured percentage

Reviewed 2026-10-16 from public Help and the literal July 2026 webinar capture.
Not current-tenant or host verification. This bounded task selects Deposit using
an already configured, business-approved percentage; it does not set a fixed-dollar
deposit or alter a reservation's Set deposit payment link.

## Confirm scope and readiness

Confirm the authorized company, role/access, paid-payment eligibility and merchant
readiness. Free has no Moovs payment processing, card charging or payment links;
do not enable this collection workflow or offer a Stripe/link workaround on Free.
Do not upgrade, connect a processor or change subscription billing incidentally.

Before any write, establish the currently configured percentage from safe existing
information and confirm it matches the approved future upfront-payment policy.
No Charge hides Charge Percent in the capture: never select Deposit just to peek
at an unknown percentage. If the configured value cannot be safely established,
pause before the toggle and obtain supported guidance; business approval of a new
percentage alone does not prove the existing configuration. Do not copy the filmed
60% example. This changes a future-reservation preference, not existing trips,
a recorded payment or money already collected.

## Operator-owned preference change

1. Open **Settings > Customer Portal > Payments**. Current Help calls the tab
   **Payment**; the July capture calls it **Payments**. Match the actual tab and
   **Reservation Payment Preference** before proceeding. Read the current mode.
2. The capture shows **No Charge**, **Deposit** and **Full Charge**. If already
   visible, compare **%** and **Charge Percent**, a percentage of **Total Amount**,
   against the pre-established approved configured value. Hidden or unknown value
   means no discovery toggle. This is not an individual reservation's Set deposit,
   Operator Charge amount, bank account or payment link.
3. Only after that pre-write check, have the operator select **Deposit**, treating
   this as an immediate write. Compare the revealed **%**/**Charge Percent** with
   that established value; if different, stop and report the mismatch, not an
   unrequested amount change or repeated toggle. The capture shows mode selection
   followed by **Saving**, then **Saved**, with the configured percentage retained.
   This observes mode saving, not percent-field autosave. Do not invent a Save
   button or borrow bank-save instructions. Leave credit-card enablement and all
   other options unchanged; payment readiness is already established.
4. Wait for saving to finish, then reopen this same company's Payment(s) tab.
   Compare **Deposit**, **%**, and **Charge Percent** with the approved percentage.
   A pre-existing Saved label or a toast is not enough. Missing, changed or unclear
   readback is incomplete; inspect before retrying an immediate-write control.

If the amount needs changing, the currency mode is selected, or these controls
cannot be reconciled with current public guidance, stop this bounded selection
and obtain supported amount-configuration instructions. Do not guess fields,
validation or fixed-dollar behavior. The capture does not film percent entry.

## Report and limits

Report the saved mode and configured percentage only after same-company readback.
Without authorized inspection, call completion operator-reported. No charge,
booking submission, payment link, email or customer impersonation is a setup test.
The future customer upfront-payment policy is not proof of collected funds,
existing-booking changes, payout timing, or receipt at the bank. A preview is not
required to complete this setting readback.
