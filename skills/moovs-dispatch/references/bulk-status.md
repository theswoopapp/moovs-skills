## Bulk status and driver edits

1. In Dispatch, review the intended list/date/filters before the operator selects
   multiple trips and opens **Bulk Edit**. November 2025 narrows the list to one
   vehicle on the intended day before selecting its trips; verify that scope.
   Review every selected reference, not
   only a visible row or aggregate count; do not assume hidden pages are included.
2. January's public demonstration changes trip status and assigns a driver in
   that bulk flow. Ask which field/value and exact trips are intended. Review
   suitability, overlaps, qualifications and possible notifications per trip;
   a shared selection does not establish every driver/vehicle is appropriate.
3. Operator reviews offered controls and submits. November 2025 narrates **Save**
   for bulk driver and status changes; use it only when current controls match.
   It does not establish every bulk-field limit, partial-failure behavior, rollback
   or a universal final button. If scope/outcome is unclear, stop before bulk retry.
4. Reopen each intended trip and compare the changed status/driver; a filtered
   row disappearing is not proof of success. Separate saved assignment from
   driver acceptance, notification delivery and actual service performance.

## Passenger Dropped Off versus garage return

March's public explanation separates **Passenger Dropped Off** from the driver's
later garage return/end. The cited narration does not establish that a named
**Done** UI state universally means garage return; inspect actual current labels
and their meaning. It describes customer completion/review messaging
at passenger drop-off, not waiting for the vehicle to return to the garage.
Check current notification configuration and actual operational evidence before
the operator records any status. Do not mark a trip dropped off/done to trigger
a message, release capacity or demonstrate a workflow when service did not occur.

Read back the exact trip's status/time and relevant activity when authorized.
Status is not proof a customer received a message, the driver reached the garage,
the trip is Closed, or payables were processed. Do not assume each program uses
identical status automation; investigate a material mismatch with Support.
