# Availability and qualifications

Reviewed 2026-10-16 (Driver App entry-point qualifier); other sections 2026-10-15.
Operator or driver performs every schedule/qualification edit.

## Review and configure availability

Driver: when Driver Availability is enabled, Menu > **Set Availability >
Set Availability** opens the web calendar.
Operator: **Settings > Drivers > driver > top-right menu > Copy Driver App Link**,
open the private link, then **Availability**. Some public guidance calls it
**My Availability**. Keep the link out of chat/public notes.

Use the Available, one-time Unavailable, edit/delete or explicitly requested
rebuild scope below. Confirm dates, working hours, overnight scope and recurrence
before changing anything. After any operator save, reopen the intended event(s),
compare times/type/repeats, then inspect coverage and assignment warnings without
making a test assignment.

Public rules: no availability settings/events ever created means treated as
available. Once a schedule exists, the trip must fit completely inside available
time; overlapping unavailable time overrides it. This default is not independent
proof the person can work. Review actual commitments and the operational need.

Trip Conflict means overlapping assigned trip; red calendar means schedule
conflict; orange triangle means missing qualification (hover to identify which).
In this selector no icon means no flagged conflict. These warnings can be
overridden, not hard safety enforcement; resolve the conflict or choose a suitable
driver rather than overriding for convenience. Green accepted/yellow awaiting/red
declined is a separate per-trip response; no response icon means no assigned driver.

## Create available working time

On the intended driver's calendar, the published walkthrough opens an empty time
slot's **Add Event** window and selects **Available**. Operator sets **FROM** and
**TO** dates/times, optionally checks **Repeat** and chooses recurrence, then uses
**Add** where these labels match. Available time can be one-time or repeat on
selected days. Compare saved coverage and recurrence with the intended hours;
do not clear existing events as a prerequisite.

## Add a one-time unavailable exception

For the exact exception inside an available period, operator creates
**Unavailable** time with the intended start/end dates and times. It cannot
repeat. Inspect actual offered controls before submission; do not assume the
Available example establishes every Unavailable editor label. Reopen the event
and compare its type/times plus the affected availability coverage.

## Edit or delete schedule time

Select the exact event to edit or remove. The newer availability guide says
removing an event belonging to a recurring setting removes that setting and its
generated repeats. The older reset guide describes deleting a block and future
repeats for that day. Do not generalize that narrower wording to every deletion
or promise which past instances survive. Review the actual confirmation and stop
if scope is unclear or conflicts with the intended correction; preserve needed
schedule details before operator deletion. Read back affected events/recurrence,
not just the disappearance of the selected block.

## Rebuild availability only when explicitly requested

For a reviewed full rebuild, the older walkthrough selects each available block,
uses **Delete > Yes, delete all**, and repeats until the calendar is empty; its
stated scope is that block and future recurring instances for the day. Reconcile
the recurring-deletion scope above before the operator proceeds. This is not
routine conflict cleanup; prefer a targeted edit when it solves the problem.
Recreate the intended working periods using the Available procedure and read back
every intended day/recurrence. Do not infer an emptied calendar restores the
never-configured default, or that rebuilding alone proves downstream suitability.

## Qualifications

Published **Pro+**. **Settings > Drivers > Qualifications > New Qualification**:
name, optional description, color, **Applies to** Vehicles or Categories, drivers
who hold it and vehicles/categories requiring it, then operator **Create**.

Vehicle and category requirements combine: a driver needs all of them to avoid
a warning. Applies to type is locked after creation. Names are unique; up to 20
active qualifications. Selecting a missing-qualification driver shows a conflict
message; **Assign** can override it. Never equate that override with legal fitness.

After creation, reopen the qualification and compare type, category/vehicles and
holders. During an authorized intended assignment review, inspect the selector's
qualification warnings too, without assigning an unsuitable driver as a test.
Saved configuration alone does not independently verify that downstream check.

To edit: **Settings > Drivers > Qualifications > intended qualification**.
Operator changes only requested name/description/color, qualified drivers or
required vehicles/categories, then uses the actual offered save control. Reopen
and compare those values; the source names no universal edit-save label.

**Applies to** cannot switch in place. For an explicitly intended wrong-type
repair, first review the replacement's correct type, name, holders and targets.
Operator opens the old qualification > **Delete Qualification**, then recreates
it through **New Qualification** with the correct Vehicles/Categories choice
and intended relationships > **Create**. Deletion removes future checks; review
that temporary scope change before acting, and do not assume relationships copy.
Reopen the replacement and compare its type/holders/targets. No driver assignment
is needed merely to verify the replacement settings.

For incorrect warning, operator reviews holders and both direct vehicle/category
requirements, saves the correction and reopens the selector without assigning as
a test. Do not delete merely to silence a warning. At the 20-active-qualification limit, the guide
allows deleting an actually unused qualification before creation; the operator
must identify/approve removal, not the assistant. Unique names still apply.
