## Templates and editing

Published navigation is **More > Website > Get Started**. Use **Preview in Browser**
to inspect a template without creating a site. The public Help template gallery
also lets you select a template image to open its information/interactive-preview
page; that is a public preview, not an account site or editing access.
Only when site creation is requested,
the operator uses **Select Template > Accept**. After generation, **Site Editor**
opens editing if the account has access. The older guide describes upgrading to
unlock editing; that is not a universal current entitlement or price statement.
Do not purchase/upgrade, create or replace a site merely to preview a template.
If generation or editing access is uncertain, confirm with Moovs first.

## Edit an existing blog post's text or image

Reviewed 2026-10-16 from February 2026 public webinar narration, not a fresh
visual or current-account inspection. Use for an **existing, open blog post**
in the intended Moovs website editor. The recording describes the post's title,
text/content and replacing/saving a picture; it does not establish an exact blog
opener, new-post creation or final text-save/publish controls.

1. Reuse the confirmed company/site/post and editing access. Agree the approved
   title/body wording or replacement image and whether publication is requested.
   Keep customer/private data and private trip/payment/driver links out of public
   content; use only an approved image the business has permission to use.
2. With the intended post open and matching content controls visible, have the
   operator change only the approved title/text or replace the intended picture.
   Explain one action at a time and wait for their result. Do not demand an
   undocumented blog opener or a new post just to edit existing content. If the
   post is not open, ask what the actual editor shows; do not invent a Blog menu.
3. Editing may persist immediately. The narration describes saving the replaced
   picture, not a universal final text-save button. Operator handles the actual
   offered save/auto-save controls; do not invent **Save Post** or require Publish
   to retain an edit. Give useful content-edit/review coaching even when the
   final text-save mechanism is not established. If the outcome is unclear,
   report edited/unknown rather than saved, and inspect before repeating edits.
4. After operator save feedback, reopen the same post when available and compare
   only the requested title/body/image, checking unrelated content is unchanged.
   Preview desktop/phone layout where offered. These are recommended readback
   checks, not results verified by the webinar. Without authorized browser
   inspection, label the checks operator-reported. Saved/editor preview is not
   public publication; never publish merely to test the change.

For a missing or materially different control, seek current public Help/Support
for that step; do not stop an otherwise supported text/image explanation.
Duda AI writing help is mentioned in the webinar, not a documented AI-button or
publication workflow. It is optional, needs human content review and does not
promise search rankings. Do not upload private information to generate copy.

## Logo, fleet and booking entry points

This is routing to five separate tasks below, not one completed website feature.
Choose the requested outcome; editing a logo does not authorize fleet publication
or changing booking buttons. Reopen saved state after an edit. Inspect the public
result only when a public update was requested and performed; otherwise label
editor/preview results and do not claim visitors can see them. The guides do not
establish a universal save/publish control; operator handles the actual controls,
including auto-save, and stops for current guidance if their behavior is unclear.

## Update the website company logo

1. Confirm the company, approved asset and company-wide branding scope, not just
   one page. For preview-only requests, inspect existing branding without upload.
2. Operator uses **Settings > General > Add Company Logo** to upload the asset.
   Do not invent a separate Save button or assume uploading is non-mutating.
3. Return to the website editor and refresh if needed. Compare the upper-left
   logo with the approved asset and saved company branding. If an approved public
   update was made, inspect the public logo too; editor appearance alone is not live.

[Logo guide](https://intercom.help/moovs-05c940f1970e/en/articles/6610578-adding-your-logo-to-your-moovs-website).

## Publish a vehicle on the website

1. Confirm the exact vehicle and approved public images/information. Do not
   publish internal notes or assume every fleet record should be public.
2. For an approved publication, operator opens the vehicle, then its upper-right
   three-dot menu > **Publish on Website**. This is not a preview-only action.
3. Open the website editor and refresh if necessary; compare the intended vehicle
   and approved content. Inspect the public site for the requested published
   outcome. Do not claim all vehicles were published from this one record.

[Fleet guide](https://intercom.help/moovs-05c940f1970e/en/articles/6610564-adding-vehicles-to-your-moovs-website).

## Change the vehicle widget layout

1. Identify the existing vehicle widget and requested layout. The guide describes
   horizontal as the default all-vehicles view and vertical as the compact view.
2. To switch to vertical, operator opens the vehicle **Design** tab, clicks
   **Horizontal Layout**, then **Vertical Layout**. Treat selection as a possible
   auto-save, not a harmless preview; do not invent additional layout controls.
3. Reopen the widget to compare the selected layout and intended vehicle content,
   including images/capacity. For an approved public update, check desktop/mobile
   presentation on the public site; otherwise report only saved/editor state.

[Vehicle widget guide](https://intercom.help/moovs-05c940f1970e/en/articles/6638207-moovs-vehicle-widget).

## Connect the website Book Now buttons

1. Confirm the intended company's general booking link, not a private trip/payment
   URL. The older button guide says **Settings > Booking Tool**; current portal
   guidance uses **Settings > Customer Portal > Installation & Share > Copy Link**.
   Reconcile differing controls instead of guessing or copying an example URL.
2. In the site editor, operator selects each relevant **Book Now/Book a Ride**
   button, sets **Website URL** to that link and selects **Open in a new window**.
   Repeat for every affected non-vehicle button. Vehicle-section buttons are
   documented as already connected: inspect before replacing them.
3. Reopen each changed button's destination/option and preview the intended
   company's booking page. Operator handles save/publication only within the
   agreed scope; after a public update, recheck affected public buttons. Do not
   submit a real quote, reservation or payment to test the link.

[Button guide](https://intercom.help/moovs-05c940f1970e/en/articles/6610626-linking-the-book-now-buttons-in-your-moovs-website-to-your-booking-tool),
[Current portal link guide](https://intercom.help/moovs-05c940f1970e/en/articles/6650028-how-to-add-moovs-to-your-website).

## Add the Moovs Booking Widget to a Moovs website

1. Confirm Moovs website/editor access, intended page and placement. This builder
   widget is not a manually wrapped Customer Portal URL or an external-site install.
2. In the website editor, open **Widgets**, search **Booking Widget**, then
   operator drags **Moovs Booking Widget** to the intended location and resizes
   it as needed. Editing can save automatically; do not do it merely to inspect.
3. Reopen the saved placement and preview its company, size and scrolling at
   desktop/mobile widths. Operator handles any approved publication; then inspect
   the public placement. Do not create a booking to demonstrate the form.

[Booking form guide](https://intercom.help/moovs-05c940f1970e/en/articles/6610599-adding-the-booking-tool-form-to-your-moovs-website).

## Website go-live is not email authentication

This is supporting scope guidance. Use the separate connect/verify-site task
below only for a requested Moovs-built website launch, not widget installation.

Custom **email** domain authenticates outbound mail and needs existing domain
and email hosting. It is a different setup from website go-live and marketing
campaign domains. The operator handles the current provider-generated records;
never request registrar credentials, invent DNS values, guarantee inbox delivery,
or copy customer-specific records into public notes.
[Email-domain distinction](https://intercom.help/moovs-05c940f1970e/en/articles/6414592-setting-up-my-custom-domain).

## Connect and verify the website domain

1. Confirm domain ownership, purchased domain, intended published Moovs-built
   site, existing hosting and a recovery plan before the operator changes DNS.
   A preview-only request authorizes no publication or DNS edit.
2. Fetch the current [go-live instructions](https://intercom.help/moovs-05c940f1970e/en/articles/9745870-how-to-go-live-with-my-moovs-website)
   for the destination values. The documented structure is **one CNAME for www**
   and **two A records for the root (@)**, for balance/redundancy. Do not reuse
   stored IPs, another account's records or email-authentication CNAMEs.
3. Operator reviews conflicts/recovery and makes only the approved website DNS
   changes at their provider. Do not delete/replace mail MX/SPF records, repoint
   an external website for a widget install or request registrar credentials.
4. After operator save, compare the saved host/type/destination records. The
   guide's CheckDNS checks have different scopes: look up the domain **without
   www** and compare its **A records**; look up **with www** and compare its
   **CNAME** against the current instructions. Report pending/mismatched results
   without repeatedly rewriting DNS or declaring success from save alone.
5. After records resolve, reopen the intended public domain and verify company,
   website content and relevant booking entry point at desktop/mobile widths.
   DNS match is not website acceptance, and a visible booking form is not an
   end-to-end booking test. Separate saved DNS, observed resolution and public-site
   results; no test booking or email send is needed for this scoped task.
