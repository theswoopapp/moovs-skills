## AI trip PDF import

The [November 2025 demonstration](https://fast.wistia.com/embed/iframe/iwtmxjqqp3)
(16:36–18:30) shows the AI import hub selecting a PDF, **Upload and process**,
processing history with an order number, and opening a generated reservation
with multiple trips. The [December follow-up](https://fast.wistia.com/embed/iframe/2cr38q63dr)
(44:34–45:56) describes single- and multi-trip creation; CSV is still upcoming
in those recordings. Neither establishes perfect extraction or safe retry rules.

1. Confirm the intended company, actual AI import access, document owner and
   desired reservation(s). Decide whether this is a normal reservation import,
   not a Shared Shuttle booking CSV or a Miles knowledge-base attachment.
2. Privately compare existing reservations/history before an upload. Explain
   that processing can create records; it is not merely a harmless preview.
   Do not send the document to the assistant or reuse a webinar example.
3. If the current authorized UI presents the demonstrated import hub, explain
   file selection and **Upload and process**; the operator selects their own
   approved file and initiates it. Do not infer a navigation path not shown in
   the public narration. If controls differ, stop and obtain current guidance.
4. Read processing history. Open the resulting order/reservation when available;
   compare trip count, contacts, dates/timezones, locations/stops, service and
   pricing against the authorized source. This comparison is a safety check,
   not a claim about supported extraction fields. Operator handles corrections.
5. Report created record(s), unresolved mismatches or unknown processing state.
   A successful upload is not a verified correct reservation. If no order appears
   or the result is uncertain, do not upload again or delete records to fix it;
   inspect history and ask Support to resolve the outcome first.

The current [pricing comparison](https://www.moovsapp.com/pricing) advertises
CSV/PDF trip uploads: Free unavailable, Standard 1/month, Pro 5/month, Enterprise
unlimited. Older demos call this Enterprise access, and the pricing FAQ still
points to Enterprise for Bulk Trip Import. Confirm actual account access/remaining
allowance rather than treating either statement as a universal guarantee.
Public sources reviewed do not define file/row/size limits, column schema,
quota reset/counting, duplicate handling, rollback or error recovery. CSV being
listed now does not establish its exact upload workflow. Do not substitute the
separately documented Shared Shuttle import or generic contact import steps.

## Partner commission tracking and referral attribution

The current [Agents Portal product page](https://www.moovsapp.com/solutions/agents-portal)
describes partner contact/type/rate/location/status and commissions tied to trips,
with owed/paid/pending visibility. The current pricing table marks the offering
under Enterprise. No reviewed source establishes partner invitation/login,
rate calculation rules, commission adjustments, payout submission or reconciliation.
Do not confuse this with Refer a Friend credits, employee compensation or
operator-to-operator farm-in/out settlement.

A separate [November 2025 demonstration](https://fast.wistia.com/embed/iframe/iwtmxjqqp3)
(49:55–51:31) explains customer-portal links, **QR codes**, UTM parameters and
custom attribution dashboards. It does not show configuring a commission ledger.
For that bounded preparation, confirm intended partner and destination; explain
copying the company's customer-portal link, creating a QR/link with agreed UTM
source and recognizable name, and operator-controlled generation. Keep actual
company/partner links private. Read back encoded destination and parameters;
link and QR should target the same intended destination. Do not submit a real
booking or publish/share the link merely to test it.

A generated link or attributed quote is not an earned commission or paid partner.
Stop before claiming dashboard attribution, commission amount or payout without
the relevant actual record/status. Request the current official setup guide for
the commission product rather than inventing rate or payment controls.

For a promo that activates only after a referred person's **first completed
ride**, September's Q&A says no out-of-box workflow existed then; API automation
is a future suggestion, not demonstrated setup. That is dated negative evidence,
not a universal current prohibition. Obtain current supported guidance before
promising event-conditional activation. UTM/QR attribution and reporting can help
review the referral, but a booking is not a completed first ride or automatic
reward eligibility. The operator must separately verify the agreed condition and
approve any [promo creation/change](https://intercom.help/moovs-05c940f1970e/en/articles/9084919);
do not activate a code, send it or call an API as a diagnostic.
